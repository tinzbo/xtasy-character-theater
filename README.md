# Xtasy Theatre · 互动角色剧场

走进一个人的世界，说出你的想法，一起把故事带向不一样的结局。

一个可以直接启动、完整游玩的中文互动故事产品。包含角色发现、品类筛选、角色详情、收藏、可恢复的剧情进度、自由文字回应、明确行动、共同记忆、结局和会话导出。媒体随仓库提供，首次启动不需要生成图片、配音或视频。

## 立即运行

要求 Node.js 22 或更新的受支持版本。首次安装：

```bash
npm ci
cp .env.example .env
npm run dev
```

打开 **http://127.0.0.1:4312**。不配置 API key 也能通过明确行动完整体验所有故事；自由文字使用已标示的关键词匹配。浏览器默认不会擅自播放声音，进入故事后点击「播放这一幕」。

如要使用 Jev 自由表达理解，在本地 `.env` 填写 `TYPESAFE_API_KEY`；密钥只由服务器读取。修改后重新启动服务。

编译并运行成品：

```bash
npm run build
npm start
```

`npm run build` 生成 `dist/` 前端和 `dist-server/index.js` 后端。`npm start` 直接运行编译后的 Node.js 程序，自动使用生产静态资源，不依赖 tsx 或 Vite 开发服务器。

开发与成品服务共用默认端口，不要同时启动。可以通过环境变量 `PORT` 指定另一个端口。

## 已交付的故事

| 角色 | 故事 | 用户目标 | 可达结局 |
| --- | --- | --- | --- |
| 林岚，28 岁，咖啡馆主理人 | 等雨停的人 | 陪她完成最后一夜，决定咖啡馆的明天 | 海风来信 / 门再次打开 |
| 沈曜，32 岁，星舰领航员 | 第七颗星的回声 | 核实求救信号，为星舰找到安全航线 | 星光同行 / 安全归航 |
| 许知秋，30 岁，档案整理师 | 夹在第九页的名字 | 核对三份档案，决定如何讲述往事 | 留白的展签 / 等待回信 |

每个故事包含 6 个中间场景和 2 个结局，共 24 个节点、24 段带中文配音的视频、6 个可达结局。不同路线会跳过部分场景，按个人选择约需 3–6 次行动完成一轮。

所有人物均为原创虚构成年人。当前媒体采用 **原创场景图 + 缓慢运镜 + Kokoro 中文神经配音 + 中文字幕**，是图像叙事视频，未实现实时口型或逐动作人物表演。影片、SRT、VTT 与校验清单已经入库；原始资产记录见 [媒体来源说明](docs/media-provenance.md)。

## 怎么玩

1. 在发现页选择角色，可以先筛选日常关系、科幻冒险或悬疑探索。
2. 进入角色详情，阅读目标并开始故事。
3. 点击播放这一幕；视频内有声音，可通过播放器调节音量、字幕和进度。
4. 用自己的话表达一个具体行动，或点击两个明确行动之一。`Ctrl/Cmd + Enter` 可以发送输入。
5. 每一步由服务器自动保存。返回剧场后，从最近演出或角色卡片继续。
6. 到达结局后，可以重开体验不同路线，也可以导出 Markdown 会话记录。

收藏和最近演出索引保存在当前浏览器；故事状态保存在服务器 `.data/sessions.json`。清除浏览器存储会清除本机的收藏和会话入口。最多保留 500 个服务器会话，浏览器保留最近 50 次演出。

## Jev 在哪里工作

Jev 只负责把当前自由文本映射到 **当前场景已经定义的候选行动**，不编写台词，不改写事实，不创造新剧情。

- 状态输入：当前角色、当前场景、用户最新回应、最近六条实际发生的记忆。
- `Choice` 选项：仅当前节点的行动，以及 `NONE`。
- 代码核验：候选合法性、概率不低于 `0.6`、集中度不低于 `0.55`；未匹配或不足时请用户澄清，剧情不推进。
- 直接点击行动：直接运行确定性状态机，不浪费模型请求。
- 密钥未配置、服务超时或并发限额时：使用界面明示的关键词匹配；匹配不明确时停留原场景。

这些阈值是当前内容包的初始工程策略，并不代表通用准确率。2026-09-27 已对三个角色各测试一个实际自由表达请求，均经 Jev 正确路由；自动化测试不调用付费服务。

集成依据：[JavaScript SDK](https://docs.typesafe.ai/sdk/javascript)、[Choice](https://docs.typesafe.ai/primitives/choice)、[Function calling](https://docs.typesafe.ai/cookbooks/function_calling)。

## 工程与验证

```bash
npm test             # 剧情、状态、存档、并发、接口和输入边界
npm run media:check  # 24 段媒体 SHA-256 与字幕检查
npm run build        # TypeScript strict + Vite 前端 + esbuild 后端
```

CI 在 Node.js 22 / Linux 上执行以上命令并对生产服务做 HTTP 冒烟验证。代码结构：

```text
src/stories.ts           原创剧本与有向无环剧情图
src/main.tsx            角色发现、收藏、历史、详情和播放体验
src/styles.css          响应式视觉与 reduced-motion
server/engine.ts        确定性状态机与关键词回退
server/router.ts        服务端 Jev 判断与保守处理
server/store.ts         JSON 持久化、串行原子写入
server/app.ts           输入校验、来源检查、限速和修订号锁
public/media/           原创场景图片与已编译音视频
scripts/                媒体生成和校验
```

默认只监听 `127.0.0.1`。会话使用随机 UUID 能力标识，客户端不能随意指定下一节点；服务器校验修订号并阻止同一会话并发覆盖。输入限 600 字，接口每 IP 每分钟最多 90 次，Jev 最多同时处理 3 个请求，模型请求有硬超时。`.env`、`.data`、媒体生成中间文件均被 Git 和 Docker 忽略。

当前版本定位为可运行的本地单用户产品与内容验证版本，不包含账户、支付、跨设备同步或多人编辑。公开部署应在外层增加身份认证与用户级存档隔离；不应把会话 UUID 当作完整账户权限系统。

## Docker 运行

```bash
docker compose up --build -d
```

容器内监听 `0.0.0.0:4312`，Compose 只映射宿主机 `127.0.0.1:4312`。存档写入 `theatre-data` volume，重建容器不会丢失。密钥由 Compose 从本地环境或 `.env` 注入，未进入镜像。

镜像构建阶段执行测试、媒体检查、前后端构建，运行阶段只安装生产依赖并使用非 root 用户。当前机器未启动 Docker daemon，因此已验证 Compose 配置与同等的生产依赖独立启动流程；容器镜像构建和容器运行尚未在本机验证。

## 内容迭代

1. 在 `src/stories.ts` 增加或调整角色、节点、明确行动和记忆。每个行动必须指向同一故事里的现有节点。
2. 同步 `data/media-script.json` 的台词、角色、图片和视频路径。
3. 按 [媒体重建说明](docs/media-build.md) 准备隔离 Python 3.11 环境与 FFmpeg，再运行 `npm run media:build`。
4. 运行测试、媒体检查、构建，再用桌面与手机浏览器完整玩一轮。

重新编译使用 Apache-2.0 授权的官方 Kokoro 中文模型，本地生成神经配音，无需付费 API。模型 revision、权重校验、音色和参数固定在 `data/tts-config.json`；许可证见 [第三方声明](THIRD_PARTY_NOTICES.md)。通常用户无需重建媒体，模型与 Python 环境不会随发布包分发。原始图像生成不是本地构建依赖。
